# Состояние и устройство проекта TelegramBot

Актуализировано по исходникам 10 октября 2026 года. Центральный справочник содержит структуру, персонажей, маршрутизацию, команды, настройки, память, ресурсы и оставшийся план улучшений. Локальные секреты и персональные записи в документацию не копируются.

Ключевые настройки: контекст каждого персонажа — 5 сообщений, диапазон 0–65535; очередь — 50 ожидающих сообщений, диапазон 1–65536; личная память по умолчанию выключена у всех персонажей и пользователей. Пол и возраст разделяют «указан пользователем» и «предположительно»; возраст и факты имеют даты обновления. Полная инструкция: [память и контекст](user_memory.md).

## Что это за проект

Одно Python-приложение Telegram на `aiogram` и один токен обслуживают семь персонажей. Текстовые ответы формируются локальной моделью через OpenAI-совместимый сервер LM Studio. Персонажи, история и настройки находятся в одном приложении; каждый персонаж хранит отдельный контекст и историю ответа.

| Путь | Назначение |
|---|---|
| `bot/main.py` | Telegram-обработчики, выбор персонажа, групповые ответы, админка и маршрутизация функций |
| `bot/personas.py` | Имена, характеры, языки, подписи говорящих и общий вызов персонажей |
| `bot/keyboards.py` | Кнопки панели администратора и меню настройки |
| `bot/state.py` | Атомарное JSON-хранилище, доступы, контексты и история |
| `bot/user_memory.py` | Факты, профиль собеседника, даты, извлечение и пользовательский просмотр |
| `bot/memory_admin.py` | Админское меню памяти, фильтры и постраничный просмотр |
| `bot/character_context.py` | Независимое окно истории каждого персонажа |
| `bot/lm_studio.py` | Вызовы OpenAI-совместимого API LM Studio |
| `bot/hardware.py`, `bot/gpu.py` | Чтение сведений о Windows, CPU, RAM, диске моделей и NVIDIA GPU |
| `bot/news.py` | Поиск новостных заголовков через GDELT |
| `bot/jokes.py`, `bot/persona_jokes.py` | Распознавание юмора и личные списки минимум по 500 тематических шуток |
| `assets/stickers/characters` | Активные праздничные WebP-наборы персонажей |
| `assets/stickers` | Реакционные стикеры Насти и прочие общие/унаследованные материалы |
| `assets/stickers/imports` | Архивные исходники перенесённых проектов, не все из которых подходят для активного образа |
| `docs` | Инвентаризация, брифы персонажей и планы наполнения |
| `scripts/bots` | Скрипты запуска и остановки найденных ботов на компьютере |

Локальные `.env`, `data/` и `logs/` исключены из Git. `.env.example` содержит шаблон конфигурации без рабочего токена.

## Реализовано

- Персонажи: Настя, Наташа, Котик Мяу, Пёсель, Ракета, Грут/Клён и Стич. Контексты персонажей и стилевых режимов написаны на английском; язык ответа задаётся отдельно.
- Администратор выбирает модель LM Studio, персонажа по умолчанию, групповой режим, общий характер каждого персонажа и язык каждого персонажа. Общие стили и «рандом» доступны всем. У Насти дополнительно есть стиль «учительница». Откровенных и кокетливых стилей нет.
- Поддержаны языки русский (по умолчанию), английский, французский, немецкий, испанский, китайский, японский, корейский, хинди, идиш, белорусский, финский и ирландский. Временная просьба ответить на другом языке относится к конкретному пользователю, чату и персонажу.
- У персонажей есть подпись говорящего. Пёсель лает, Котик мяукает, Стич отвечает в мультяшном стиле, Грут включает фразу «Я есть Грут».
- Общие обращения к команде вызывают всех семерых в случайном порядке, последовательно. Несколько имён вызывают только перечисленных; «подруги» без «друзья» — Настю и Наташу. Очередь чата предотвращает перемешивание вызовов. Распознаются русские и английские имена.
- Владелец может ограничить пользователей по Telegram ID или по `@username` в ответе на сообщение пользователя; права на системные данные выдаются и отзываются теми же способами. Произвольный username без сообщения Telegram Bot API не разрешает найти. Чаты настраиваются отдельно. `/deny_here` отключает ответы в текущей группе или по ID/username из личного чата, `/leave_here` выводит бота из текущей группы, `/leave_chat ID|@username` позволяет из личного чата вывести его из группы или канала; команды очищают чат из списка разрешённых. Все административные команды и callbacks проверяются по числовому `OWNER_ID`; добавление бота в группу также сверяется только с этим ID. Режимы группы: `mentions`, `keywords`, `context`, `all`.
- Обычный контекст задаётся отдельно каждому персонажу: 5 сообщений по умолчанию, от 0 до 65535. Общая история ссылок на сообщения хранит 50 событий по умолчанию; это отдельная настройка. Можно ответить на сообщение напрямую или попросить вернуться к предыдущему сообщению по номеру. Общая FIFO-очередь генерации обслуживает все чаты последовательно; лимит 1–65536 ожидающих сообщений, по умолчанию 50, задаётся в `/admin` или `/queue_limit N`. При переполнении самое старое ожидающее сообщение удаляется молча; выполняемое не прерывается.
- Ретроспективный анализ: персонажа можно попросить прочитать последние N сообщений автора в текущем чате. Без числа выбирается 10–30 случайных сообщений; владелец настраивает лимит хранения от 0 до 65 535 (по умолчанию 100) в `/admin` или `/analysis_limit N`. Ноль отключает функцию; в группах сообщения разных авторов не смешиваются.
- Есть обработчики праздничных стикеров, реакций, шуток, новостей и запросов состояния компьютера. Сведения о железе только читаются; доступ контролируется отдельно.

Темы компетенции и примеры вызовов описаны в [правилах персонажей](character_behavior.md).

## Проверки и Git

Исторически выполнялись регрессионные проверки маршрутизации и очереди. Для текущих изменений отдельно проверены память и индивидуальное окно контекста; актуальная запись о проверках приведена в подробном разделе ниже. Полная интеграционная проверка Telegram + LM Studio не подтверждена.

Историческая сводка упоминала коммит `7c26239`; это не подтверждение, что текущая рабочая копия закоммичена. Текущее состояние проверяется через `git status`; не считать изменения опубликованными без отдельной проверки.

Праздник без имени вызывает стикеры всех семерых по очереди. Имена и алиасы ограничивают вызов указанными персонажами. Полный справочник: [CHARACTER_ALIASES.md](../CHARACTER_ALIASES.md). Проверки включают все шесть праздников, личные и совместные алиасы и вызов в разрешённой группе.

Случайные стикеры: «стикер»/«картинка» без имени выбирает случайного героя и файл его активной коллекции; имя или алиас фиксирует героя. Поддерживаются sticker, picture, image. Общие и совместные вызовы отправляют по стикеру от каждого по очереди.

Эмоциональные стикеры завершены: по восемь для каждого из семи персонажей (56 файлов). Формат каждого — RGBA WebP 512×512 с прозрачностью; размер, формат и комплектность сверены. Распознавание настроений и вызов эмоций добавлены в `bot/emotions.py` и `bot/main.py`; полноценные интеграционные тесты изменения здесь не выполнялись. Детали и статусы: [docs/emotion_stickers.md](emotion_stickers.md).

## Очередь входящих запросов

Все разрешённые текстовые сообщения и стикеры проходят через одну FIFO-очередь. Один worker запускает обработку следующего элемента после завершения предыдущего, в том числе удерживает всю последовательность командного вызова персонажей в одном слоте. Настраиваемый лимит — от 1 до 65 536 ожидающих сообщений; начальное значение 50, текущая настройка видна в админке. Владелец выбирает быстрые значения в `/admin` или задаёт любое точное число командой `/queue_limit N`. При переполнении удаляется самое старое ожидающее сообщение без ответа, новое добавляется в конец; если лимит уменьшили, при следующем поступлении удаляются старые запросы, пока не появится место. Уже выполняемый запрос не прерывается. Перед добавлением проверяются доступ пользователя и чата.

| `bot/main.py` | aiogram Router, команды и callbacks, ACL, очередь, выбор маршрута, сборка промпта, отправка результатов |
| `bot/personas.py` | Персонажи, языки, именные шаблоны и опечатки, командные обращения, темы, голос и подпись |

| `bot/config.py` | Загрузка `.env` и проверка обязательных параметров |
| `bot/lm_studio.py` | HTTP-клиент `/models`, `/chat/completions`, закрытие соединений |
| `bot/emotions.py` | Восемь эмоций и русские/английские алиасы |
| `bot/jokes.py` | Распознавание запросов юмора и категорий |
| `bot/persona_jokes.py` | Собственные шаблонные банки шуток по темам персонажей |
| `bot/news.py` | Предопределённые поисковые запросы GDELT, разбор и нормализация заголовков |
| `bot/hardware.py`, `bot/gpu.py` | Только чтение показателей компьютера, psutil, Windows/CIM и NVIDIA |
| `assets/stickers` | Активные WebP Насти; подпапки её эмоций, остальных персонажей и архивных импортов |
| `tests` | Маршрутизация, память, окно контекста; подмены внешних сервисов |
| `start_bot.bat` | Пользовательский запуск на Windows; основной исполняемый модуль — `bot` |
| `scripts/bots/manage_bots.ps1` | Поиск интегрированных проектов рядом, start/stop/restart/kill; процессы сверяются по пути интерпретатора и `-m bot` |
| `scripts/bots/*_all_bots.bat` | Обёртки над управлением процессами; это не Telegram-команды |
| `.env.example`, `requirements.txt`, `.gitignore` | Шаблон окружения, зависимости, исключения локальных данных |
| `data/state.json` | Локальное состояние; создаётся приложением, не публикуется |
| `logs/bot.log` | Локальные журналы с ротацией; не публикуются |

Зависимости: aiogram `>=3.13,<4`, httpx `>=0.27,<1`, python-dotenv `>=1.0,<2`, psutil `>=7.0,<8`. При запуске читаются конфигурация и JSON-состояние, создаются HTTP-клиент LM Studio, Bot и Dispatcher, включается polling Telegram. Worker очереди создаётся при поступлении первого запроса. При остановке worker отменяется, HTTP-клиенты закрываются. Невыполненная очередь не сохраняется на диск и после перезапуска теряется.

Админский язык действует для персонажа в целом. «Наташа отвечай на английском» сохраняет переопределение для данного чата, пользователя и персонажа до следующей просьбы; это не однократное переключение. Перевод животных следует выбранному языку, подписи и фраза Грута сохраняются. Это стандартные Unicode-эмодзи, не собственные анимированные Telegram emoji.

## Путь входящего сообщения

Короткие продолжения «ещё», «хочу ещё», «продолжай» и английские more/I want more/one more/another one/continue/go on разрешаются до обычного выбора маршрута (`bot/continuation.py`). Без имени берётся последний ответивший персонаж; с именем — выбранный. Источник ограничен его индивидуальным окном событий текущего пользователя и чата. Сохраняется ссылка на исходный запрос, чтобы повторные продолжения не теряли тему. Если источника нет, задаётся уточнение. Оригинальный текст сохраняется в событиях и передаётся извлечению личных фактов; реконструированный контекст не становится новым утверждением пользователя. Для готовых стикеров/шуток повторяется соответствующий маршрут, для текста модель получает просьбу продолжить без повторения последнего ответа. Случайные готовые материалы пока могут повторяться.

1. Специальные Telegram-команды и админские callbacks обрабатываются зарегистрированными обработчиками. Обычный текст и входящий стикер идут в `process_chat_message`.
2. До очереди проверяется доступ: владелец разрешён автоматически, другим нужен `allowed_users`; группам и каналам дополнительно нужен `allowed_chats`. Боты-отправители игнорируются. Посты каналов обрабатываются отдельно и не получают личные записи пользователя.
3. Сообщение помещается в общую FIFO-очередь. При переполнении удаляются старые ожидающие элементы без ответа. Один worker выполняет `_process_chat_message`; доступ проверяется повторно перед обработкой.
4. Запрос своей памяти распознаётся раньше железа, выбора случайного героя и обращения к модели: возвращаются реальные записи по ID отправителя, без генерации.
5. Разбираются имена, команда, история для анализа, эмоции, стикеры, юмор, тема, железо, новости, праздник и ссылки на прошлые сообщения. Имя фиксирует героя; несколько имён вызывают перечисленных. Коллективное обращение вызывает всех, «подруги» — двух девушек.
6. Без имени выбирается тематический специалист. Общий прямой вызов бота в личке, упоминанием или ответом его сообщению выбирает случайного героя. Для стикера/эмодзи без имени также случайный герой. Сохраняется персонаж по умолчанию как запасной вариант. Общая игровая тема без имени направляется Гаву или Мяу, включая прямое обращение к боту; явное имя сохраняет приоритет.
7. Проверяется групповой режим. `all` разрешает все сообщения; `keywords` и `mentions` учитывают не только имя/упоминание, но и распознанные команды, темы, эмоции и служебные запросы. `context` может отправить сообщение модели, которая решит ответить или вернуть `[NO_REPLY]`. Названия режимов не означают строгую фильтрацию только по одному виду сигнала.
8. Уточняется язык. Прямой reply и «ответь на -1/-2» добавляют цитируемые данные. Для анализа истории берутся прошлые сообщения автора; текущая команда исключается.
9. Железо обрабатывается раньше командной рассылки и требует отдельного системного доступа. Затем командный запрос последовательно вызывает каждого героя в перемешанном порядке внутри одного элемента очереди. Вложенные вызовы не ставятся заново в очередь.
10. Специализированные ответы: отключённый анализ, эмоция, случайный стикер, анекдот, новости, тематические ограничения, праздничные/реакционные стикеры. Если подходит такой маршрут, обычная генерация не запускается.
11. Для модельного ответа проверяется выбранная модель, собираются системные инструкции, история в окне персонажа и текущий запрос. Ответ `[NO_REPLY]` удаляет статус без сообщения пользователю. Ошибки LM Studio дают сообщение о недоступности сервера.
12. Успешный ответ сохраняется в обычную историю, форматируется с подписью/голосом, разбивается на части до 4000 символов. При включённой личной памяти отдельный запрос к модели обновляет факты, затем записывается событие ответа; иногда отправляется реакционный стикер. После завершения worker берёт следующий запрос.

Административные команды, callbacks и ряд служебных команд обходят FIFO. Это позволяет менять настройки, пока модель занята, но означает, что выражение «абсолютно все операции в очереди» неверно. Очередь сериализует разговорную обработку и вложенные вызовы команды.

### Как собирается системный промпт

Общая роль Telegram-бота → фильтр адресованности для режима context → стиль → выбранный персонаж → его базовый промпт → дополнительный контекст владельца → правила цитат и голоса → тематические границы → язык → ограничение откровенного контента → правила анализа → Telegram-профиль отправителя → включённые личные факты. Затем идут предыдущие сообщения выбранного персонажа и текущий запрос.

Источники: `MODE_PROMPTS` и сборка в `main.py`; `PERSONA_DEFAULT_PROMPTS` и `PERSONA_TOPIC_PROMPTS` в `personas.py`; Настя — `SYSTEM_PROMPT`, а если он пуст, встроенная заготовка доброй учительницы физики и математики; Гав — `PESEL_SYSTEM_PROMPT` либо встроенная заготовка; дополнительный текст — `persona_prompts` в состоянии, для старой Насти также `system_prompt`. В админке дополнительный текст ограничен 8000 символами. Он дополняет базовую роль, а `/reset_prompt` удаляет дополнение. Полного единого файла финального промпта нет: он собирается для каждого запроса. Локальное содержимое `.env` и личных фактов в справочник не выгружается.

## Все виды памяти и контекста

| Механизм | Ключ / разделение | По умолчанию и пределы | Использование / очистка |
|---|---|---|---|
| Обычный контекст | `history[chat:user:persona]` | 5 сообщений на персонажа; 0–65535 | Предыдущие реплики пользователя и героя, текущая отдельно; `/context_window`, меню персонажей; 0 выключает и обрезает историю |
| История ссылок | `dialogue_events[chat:user]` | 50 событий, меню 10/20/30/50/75/100/150/200 | Reply, «сообщением выше», «через одно», `-1/-2`; события могут быть текстом или отметкой стикера |
| Архив анализа | `analysis_messages[chat:user]` | 100; 0–65535 | Последние N сообщений автора, без числа случайно 10–30; 0 отключает; хранится до limit+1 с учётом текущей команды |
| Личные факты | `personal_memories[persona:user]` | Выключено; до 30 строк по 240 символов | Условие: включены персонаж, пользователь и доступ к боту; доступно между чатами одного пользователя; отдельная очистка |
| Язык разговора | `conversation_languages[chat:user:persona]` | Переопределения нет | Просьба сменить язык сохраняется; это настройка, не история |

Личная память не является общей памятью всех людей: сведения одного ID не используются для другого. Факты разделены по персонажам, но не по чатам: при общении того же человека в другой группе персонаж видит свои прежние заметки. Обычный контекст, ссылки и анализ разделены по чатам. Память не восстанавливает неизвестные Telegram-сообщения задним числом: бот анализирует только наблюдавшиеся и сохранённые сообщения; в группах видимость дополнительно зависит от прав и privacy mode Telegram.

Команды просмотра: `/memory` или «память обо мне» — все герои о текущем отправителе; «Наташа память», «Наташа память обо мне», «Наташа /memory» — её записи. Имя для подписи берётся из Telegram-профиля отправителя, не из модели; выбор записей идёт по ID, даже если запрос — reply чужому сообщению. Просмотр возможен при выключенных переключателях; в группе результат виден участникам той же группы. Простое «память» остаётся запросом RAM.

Извлечение фактов выполняется после успешного обычного текстового ответа отдельным вызовом LM Studio. Вход: предыдущие факты и исходный пользовательский текст до 4000 символов. Инструкции требуют сохранять явно сообщённые сведения о себе, предпочтения и планы, учитывать исправления, исключать секреты, чужие данные и выдумки. Это модельная инструкция, не гарантированный фильтр. Ожидается JSON-массив объектов `fact`/`evidence`; прежний массив строк поддерживается для совместимости с моделями. Точная цитата из текущего сообщения обновляет дату подтверждения факта; неверный формат/ошибка оставляют старые записи. Проверка ревизии не позволяет вернуть заметки, которые владелец очистил во время извлечения. Стикеры, готовые анекдоты, железо и анализ архива новые факты не формируют.

Очистка `/clear` удаляет обычную историю всех героев, события ссылок и архив анализа текущего пользователя в текущем чате. Админское «Очистить историю всех чатов» делает то же для всех. Личные факты этими действиями не удаляются. В меню личной памяти можно удалить всю память, все записи выбранного героя или записи пользователя у всех героев. Выключение переключателей факты не удаляет. Уменьшение индивидуального окна обрезает историю героя; увеличение не возвращает удалённое. Окно 0 не выключает отдельно включённую личную память и архив анализа.

При анализе обычная история LM не добавляется повторно. `fit_analysis_messages` ограничивает текстовую выборку приблизительным бюджетом, максимум 12000 символов; реально использованных сообщений может быть меньше запрошенных. «Психологический возраст» формулируется как осторожная не клиническая оценка стиля общения, а не измерение или диагноз.

Поля с произвольным числом задаются указанными командами, в inline-меню предлагаются готовые значения. У личной памяти есть переключатели героев и пользователей, просмотр записей пользователя, пагинация по 20 пользователей и очистка.

| `sticker_pool` | До 50 file_id стикеров, сохранённых из сообщений владельца |

`StateStore` сериализует изменения через локальный asyncio-lock. JSON записывается во временный файл рядом с основным, сбрасывается на диск и атомарно заменяет основной через `os.replace`; при сбое состояние в памяти откатывается. `update_many` сохраняет связанные ключи одним действием: факты вместе с датами, окно персонажа вместе с обрезанной историей. `get/get_history` возвращают копии. Повреждённый JSON останавливает запуск с ошибкой, а не молча сбрасывает память. Резервные копии пока не создаются. Это не база данных и не межпроцессный lock. Не запускать два polling-процесса для одного токена/одного файла состояния. `.gitignore` исключает `.env`, `data/`, `logs/`, ключи, сессии, базы и виртуальное окружение. Исключение не удаляет уже отслеживаемые файлы и не очищает старые коммиты; полноценная проверка истории секретов и авторства — отдельная операция, здесь не подтверждается.

Логирование: консоль и `logs/bot.log`, ротация 5 MiB, три резервных файла. Входящие сообщения логируются с ID, username и текстом; функция redaction маскирует известные форматы Telegram-токенов/API-ключей/Bearer, но не любые личные сведения. Это существенное отличие от одного лишь хранения кратких фактов.

## Стикеры, юмор, новости и железо

**Праздники:** Новый год, Рождество, 8 марта, 23 февраля, 1 мая, 9 мая. Без имени все семь отправляют по своему подходящему стикеру последовательно в случайном порядке. С именами — только названные. Пути Насти: `assets/stickers/nastya_<holiday>_*.webp`. Остальные: `assets/stickers/characters/<persona>/holidays`, у Пёселя плоские имена, у других подпапки праздников.

**Коллекция:** «стикер», «картинка», sticker/picture/image выбирают героя, затем файл. У Насти берутся `nastya_*.webp` плюс эмоции; файлы с пометками adult и flirt в обычный случайный выбор не попадают. У остальных выполняется рекурсивный поиск WebP только внутри каталога героя, поэтому праздники и эмоции могут попасть в обычную случайную коллекцию. Архив `assets/stickers/imports` не используется этим поиском. Откровенный запрос стикер не получает.

**Эмоции:** грустный, счастливый, злой, агрессивный, добрый, радостный, печальный, язык наружу. «Эмодзи» без имени — случайный герой и эмоция; «Настя эмодзи» — её случайная эмоция; «Настя злая» — конкретная. Алиасы распознаются по `bot/emotions.py`. Стикеры не получают текстовую подпись говорящего. Нет доказательства, что все новые изображения прошли ручную визуальную приёмку: комплектность файла не равна сходству с образом.

**Реакции:** смех и радость могут вызвать готовую семейную реакцию. Откровенный запрос стикер не получает и уходит в короткий отказ в семейном формате. После некоторых модельных ответов возможна тематическая реакция; сохранённый `sticker_pool` и локальные файлы используются в соответствующих ветках. Ошибка отправки такого дополнительного стикера не должна отменять уже отправленный текст.

**Юмор:** распознаются «анекдот», «юмор», «насмеши», «хохма» и другие алиасы/темы. Без имени выбирается герой с учётом правил маршрутизации, с именем — конкретный. Банки локальные: темы × авторские шаблоны, минимум 500 комбинаций на героя; это не 500 вручную отобранных независимых анекдотов. Повторы между запросами не исключаются. Взрослые категории требуют явного запроса и допустимого персонажа. На другом языке готовый текст может переводиться через LM Studio, поэтому не вся «готовая фраза» работает без модели.

**Новости:** `bot/news.py` ищет до восьми заголовков за последние 24 часа через GDELT DOC API, сортирует по дате, убирает дубли и отдаёт ссылки. Страны/темы берутся из предопределённых списков, произвольный текст не исполняется как команда. Поддержаны новости мира, России, США, Китая, Украины, Британии, Индии, Японии, Кореи, Европы; темы политики, ИИ, железа, программирования, экономики, науки, космоса и другие из `REGIONS`/`TOPICS`. Это заголовки, не чтение полного содержимого статей. Требуется внешний интернет; ошибки/пустая выдача обрабатываются отдельно.

**Железо:** CPU, RAM/swap/модули памяти, GPU/VRAM/датчики, ОС и диск моделей. GPU зависит от NVIDIA/доступных инструментов, датчики могут отсутствовать. Ничего не разгоняет и не меняет. Доступ — только OWNER_ID либо `system_info_users` при уже разрешённом разговорном доступе. Агрегированный запрос собирает сведения параллельно, но занимает один слот разговорной очереди. Статусы общие, без имени персонажа.

Алиасы: GPU — видео/video, видеокарта/gpu/гпу, графика/graphics/grapphics, 3d accelerator/3д акселератор/ускоритель, VRAM; CPU — процессор/проц/камень/cpu/цпу; RAM — память/оперативка/ОЗУ/RAM/DDR/swap; диск — накопитель/диск/storage/drive/SSD/NVMe/HDD/винт; ОС — Windows/винда/операционка; всё — «железо», «характеристики компьютера». Распознавание включает поиск подстрок и имеет приоритеты: весь компьютер → диск → ОС → CPU → GPU → RAM → температура как GPU. Из-за широких алиасов обычные слова могут ошибочно направить разговор в железо: это известная задача ниже.

## Проверки и улучшения

### Выполненное упорядочивание

- Личные факты и профиль отделены от Telegram-админки: `user_memory.py` отвечает за данные и правила, `memory_admin.py` — за навигацию и фильтры, `character_context.py` — за обычную историю.

- Явное имя персонажа имеет приоритет; игровые вопросы без имени выбирают Гава/Мяу, общий нетематический вызов — любого героя.
- `/help` перечисляет всех семерых, просмотр памяти и команды управления лимитами; объясняет отличие очистки истории от личных фактов.
- Центральный справочник, пользовательская инструкция памяти и примеры запросов согласованы с текущим кодом. Выполненные исправления исключены из будущего плана.


На этой ревизии документации проверяются локальные синхронные тесты маршрутизации, личной памяти и окна контекста, компиляция и корректность diff. Асинхронные Telegram-подмены и живую интеграцию нужно проверять отдельно; их наличие в `tests` не означает, что они прошли именно сейчас. Полный запуск может зависеть от окружения. Реальные токен, сервер, выбранная модель, права и внешний интернет этой документацией не проверены.

Относительные файловые ссылки центрального справочника проверены: отсутствующих файлов нет. Подсчёт активных ассетов выполнен непосредственно через функции выбора стикеров; числа приведены в приложении.

Английские алиасы: Natasha, Nata, Natusik, Nataha, Natakha, Natka, Blonde, Blond, Blondinka, Natashenka, Natashka.

Падежные формы: Наташи, Наташе, Наташу, Наташей; Наты, Нате, Нату, Натой. Также распознаются окончания слов на наташеньк-, наташк-, натах-, натусик-, натк-, блондинк-. Регистр не важен. Алиасы работают в личных обращениях, списках нескольких имён и праздничных запросах.

### Ограничения распознавания

Опечатки и растянутые буквы обрабатываются дополнительной логикой в bot/main.py и bot/personas.py. Совместный вызов определяется по явно распознанным именам; исправление случайной опечатки не гарантирует вызов нескольких персонажей. Широкие алиасы вроде «рыжая», «учительница», «кошка», «енот» могут срабатывать при упоминании этих слов в обычной фразе: это существующее поведение. Оскорбительные прозвища Настю не вызывают.

### Запросы случайного стикера

«Стикер» или «картинка» без имени — один случайный персонаж и один случайный стикер его активной коллекции. «Настя стикер», «Натусик картинка», «Blonde sticker» — только указанный герой. Английские команды: sticker, picture, image. «Команда картинка» — по стикеру от всех последовательно.
