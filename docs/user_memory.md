# Память о пользователях

В `/admin` → **Память о пользователях** владелец управляет долговременными заметками всех семи персонажей. У каждого персонажа свои записи о каждом Telegram ID. Они сохраняются в локальном `data/state.json`, который исключён из Git, и переживают перезапуск.

Реализация разделена на данные и правила (`bot/user_memory.py`), админское меню и фильтры (`bot/memory_admin.py`), обычное окно контекста (`bot/character_context.py`) и хранилище (`bot/state.py`). Факты и их даты сохраняются одним обновлением; файл заменяется атомарно. Если JSON повреждён, запуск останавливается с объяснением, сохраняя файл для восстановления.

По умолчанию память выключена **у всех персонажей и пользователей**. Чтобы начать:

1. Включите нужного персонажа кнопкой с его именем.
2. Откройте **По пользователям**, выберите разрешённого пользователя (или владельца) и включите память.
3. При следующих текстовых разговорах персонаж будет сохранять полезные факты, которые пользователь сообщает о себе, и учитывать свои записи при ответах этому пользователю.

Память действует только при двух включённых переключателях и действующем доступе пользователя к боту. Один переключатель пользователя действует для всех персонажей, но заметки остаются отдельными. Telegram ID сохраняет привязку при смене ника. Удалённые из разрешённых пользователи остаются в списке, если о них есть записи: их можно просмотреть и очистить, включить снова можно после возврата доступа.

В карточке пользователя есть кнопки просмотра всех персонажей и отдельных героев. Кнопка очистки удаляет записи о нём у всех персонажей. В основном меню кнопка **Очистить** возле имени удаляет записи этого персонажа обо всех пользователях. **Очистить всю личную память** удаляет все заметки. Выключение памяти сохраняет заметки, но прекращает их использование и обновление. Административное управление и просмотр чужих записей доступны только владельцу; пользователь может посмотреть собственные записи.

### Просмотр владельцем в админке

В `/admin` → **Память о пользователях** доступны четыре вида просмотра:

| Что посмотреть | Путь |
|---|---|
| Вся память обо всех | **Посмотреть всю память** |
| Вся память конкретного персонажа обо всех пользователях | **Смотреть** возле имени → **Вся память персонажа** |
| Все персонажи о конкретном пользователе | **По пользователям** → ID → **Вся память о пользователе** |
| Конкретный персонаж о конкретном пользователе | **По пользователям** → ID → имя героя; либо **Смотреть** возле героя → ID |

Записи показываются страницами с именем персонажа, ID пользователя и датами обновления. Длинная память не обрезается: есть кнопки перехода. Просмотр не включает память и не меняет переключатели. Отдельные кнопки включения и очистки сохраняются. При выключенной памяти сохранённые записи тоже доступны. Все новые callbacks проверяют OWNER_ID до чтения состояния. Пользователи по-прежнему могут смотреть только собственные записи через `/memory`.

Обновление выполняет выбранная модель LM Studio отдельным последовательным запросом после отправки текстового ответа. В память помещаются до 30 коротких фактов на пару «персонаж — пользователь», каждый до 240 символов. Модель получает указание сохранять только явно сообщённые факты, предпочтения и планы, учитывать исправления и просьбы забыть факт; не делать выводов о диагнозах и не сохранять пароли и ключи. При некорректном JSON или ошибке модели предыдущие записи сохраняются. Точность извлечения зависит от модели; гарантированное удаление выполняется кнопками админки.

Стикеры, готовые анекдоты, системная статистика и запросы анализа архивных сообщений не формируют новые заметки. Память начинается с новых текстовых разговоров после включения, старый архив автоматически не обрабатывается.

Это отдельный механизм от **Контекста каждого персонажа**, **Истории ссылок** и **Анализа истории**. Очистка личной памяти не удаляет историю переписки, а очистка истории не удаляет личные заметки. Чтобы убрать сведения из всех источников контекста, очистите оба вида памяти. В одной группе записи привязаны к отправителю сообщения, а не ко всем участникам группы.

## Окно контекста персонажа

Отдельное слово `память`, а также `оперативная память`, `RAM`, `ОЗУ` относятся к статистике оперативки (доступ к данным системы проверяется отдельно). Для личных записей используйте `/memory`, `память обо мне` или имя персонажа: `Наташа память`.

В выдаче персонаж и пользователь подписаны раздельно: «Наташа — память о пользователе: Иван (@ivan)». Имя и ник берутся из Telegram-профиля фактического отправителя запроса, а записи выбираются по его ID. Модель не генерирует имя для этой подписи.

Извлечение памяти также получает раздельные поля `sender` (ID и профиль пользователя) и `bot_character` (ключ и имя героя). Имя пользователя не хранится как сгенерированный факт: оно передаётся отдельно из Telegram. Старые строки вида «Имя пользователя — Наташа» автоматически удаляются из сохранённых заметок при запуске, просмотре и использовании памяти; остальные факты сохраняются. Такой же фильтр применяется к новым результатам модели. Модели запрещено переносить биографию/пол персонажа на пользователя. Этот фильтр исправляет подмену имени, но не подтверждает достоверность всех прочих старых заметок.

Пол/род обращения фиксируется по прямому сообщению о себе: `Я мужчина`, `Я он`, `Обращайся ко мне в мужском роде`; аналогично для `Я женщина`, `Я она`, женского рода. Обращение с именем героя и запятой тоже поддержано: `Наташа, я мужчина`. Цитаты, рассказы о другом человеке, ник, аватар, пол героя и неоднозначные глаголы не используются для такой отметки. При включённой памяти отметка сохраняется у выбранного персонажа и имеет приоритет над ошибочными женскими/мужскими формами старого контекста. Повторное прямое уточнение заменяет прежнюю отметку. При выключенной памяти уточнение действует на текущий ответ без долговременной записи. Это заявленное пользователем обращение, не медицинское определение пола. Чтобы исправить ранее накопленную память, после обновления сообщите персонажу `Я мужчина` или нужную форму обращения.

### Подтверждение, предположения и даты

- Прямое заявление: **Пол — указан пользователем: мужчина; мужской род, обращение «он»**. Это заявление пользователя, не независимая проверка.
- Косвенный сигнал вроде `я писал` или `я выбирала`: **Пол — предположительно: мужчина/женщина**. Это отдельная, менее надёжная отметка. Она не заменяет прямое заявление. Нет сигнала — пол не угадывается.
- `Мне 45 лет` или `мне 45`: **Возраст — указан пользователем: 45 лет (на 2026-10-10)**. `Мне около 45 лет` сохраняется как **предположительно** с той же датой. Стиль письма и оценка психологического возраста не определяют реальный возраст.
- При чтении прибавляются полные годы с даты отметки: 45 на 2026-10-10 → 46 на 2027-10-10. До годовщины остаётся 45. Исходные возраст и дата сохраняются, каждый просмотр не перезапускает отсчёт. Без даты рождения это расчёт от даты сообщения, а не точное определение дня рождения.
- Новое прямое уточнение, например `Нет, мне 16`, заменяет прежнее значение и ставит новую дату. Теперь отсчёт идёт от 16 и новой отметки. Предположение не перекрывает явно сообщённый возраст.
- Для остальных личных фактов раздел `personal_memory_fact_dates` хранит дату последнего изменения/подтверждения по паре «персонаж — пользователь». При извлечении модель возвращает факт и точную цитату из текущего сообщения (`fact`, `evidence`); действительная цитата позволяет обновить дату ранее известного факта. Неизменённые сведения без нового подтверждения сохраняют прежнюю дату. Новая работа, предпочтение или другое исправление должны заменить противоречающую запись, а не дополнять её; семантическое сопоставление выполняет модель, его точность зависит от неё.
- Даты показываются при просмотре и передаются в контекст. Для старых фактов без сохранённых дат историческая дата не выдумывается. Очистка личной памяти также очищает даты. Часовой пояс отметок — Москва (UTC+3).

Сохранение всех этих отметок по-прежнему требует включённой памяти у персонажа и пользователя. Прямое уточнение учитывается в текущем ответе и при выключенной памяти.

Собственные записи можно посмотреть командами `Наташа память`, `Наташа память обо мне`, `Наташа /memory` (один персонаж) или `/memory` (все персонажи). Поддерживаются именные алиасы и команды Telegram с суффиксом `@имя_бота`, например `/memory@my_example_bot`. Выводятся только записи о фактическом отправителе, даже если команда отправлена ответом другому человеку. Просмотр доступен разрешённым пользователям и при выключенной памяти. Посты каналов не получают личные записи. В группах ответ виден в том же чате, где запрошен. Запрос обрабатывается без модели и не добавляется в память.

В `/admin` → **Контекст каждого персонажа** задаётся глубина обычной переписки отдельно для каждого персонажа: по умолчанию **5 сообщений**, диапазон **0–65535**. Считаются предыдущие сообщения пользователя и ответы персонажа; текущий запрос добавляется отдельно. История разделена по чату, пользователю и персонажу. Настройка персонажа действует для всех его собеседников и сохраняется после перезапуска.

В меню есть готовые значения. Произвольное число задаётся командой владельца, например `/context_window Настя 17`, `/context_window cat 30` или `/context_window Грут 0`. Ноль отключает передачу и хранение обычной истории этого персонажа. Уменьшение окна обрезает сохранённую историю; увеличение начинает накапливать больше новых сообщений, удалённые не возвращаются. Максимальное окно не увеличивает техническую вместимость выбранной модели LM Studio: очень большие истории могут не поместиться в её контекст.

**История ссылок** определяет общий архив для обращений «ответь на -1 сообщение», **Анализ истории** — отдельный архив для анализа последних N сообщений. Они не меняют индивидуальное окно персонажа. Долговременные заметки о пользователе управляются отдельно и при включении продолжают работать даже с окном 0.
