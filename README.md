Интересные мысли, и штука уже полезная: бот работает с локальной моделью. Сейчас это во многом баловство. Дальше появится прикладной функционал и интеграция с другим проектом, Notio.

Telegram-бот отвечает через OpenAI-совместимый API LM Studio на вашем компьютере. Владелец управляет моделью и стилем из личного чата с ботом; в группах можно отвечать только на упоминание или на каждое сообщение.

## Возможности

Подробный справочник всех функций, персонажей, команд, настроек, памяти, ресурсов и плана улучшений находится в [структуре и состоянии проекта](docs/project_status.md). Там же приведены полные алиасы, встроенные промпты и каталог функций. Раздельный прогресс по героям — в [таблице персонажей и материалов](docs/character_asset_status.md).

Фразы и примеры обращений с ожидаемым персонажем или типом ответа собраны в [инструкции по запросам](docs/request_examples.md).

- Это один Telegram-бот и один токен с семью персонажами: Настя, Наташа, Котик, Пёсель, Ракета, Грут/Клён и Стич. При прямом обращении без имени выбирается один случайный персонаж из всех семи; явное имя выбирает этого героя, а запрос по профильной теме — соответствующего специалиста. Персонаж по умолчанию настраивается в админке для контекстных групповых ответов. У каждого своя история и свой настраиваемый дополнительный контекст.
- Настя — добрая и отзывчивая учительница физики и математики и специалист по IT. Она спокойно объясняет тему, отвечает на вопрос и поддерживает собеседника. Общие режимы общения не меняют её уважительный семейный тон: без флирта, интимных намёков, мата, оскорблений и унизительных прозвищ. Отдельно для неё есть стиль «учительница».
- Наташа — взрослая блондинка, литератор и творческая личность: пишет стихи и рассказы, поёт, танцует и рисует; её сильные темы — психология, семейные отношения и общие медицинские знания. Она поддерживает и объясняет, но не ставит диагнозы и не назначает лечение.
- Котик Мяу — умный, хитрый, заботливый и осторожный. Он чёрно-белый, с преобладанием чёрного: белый воротник, пятно вокруг левого глаза, звезда на лбу и белые лапки-ботиночки.
- Пёсель — умная шотландская овчарка (колли), верный и заботливый защитник; он заступается за своих, не ищет драк и не угрожает.
- Стич — весёлый, игривый синий пришелец.
- Ракета — енот, сообразительный инженер и изобретатель.
- Бот принимает Telegram-стикеры как сообщения, использует их emoji/название набора как подсказку для ответа и иногда отправляет стикеры Насти по контексту: сон, приветствие, физика, IT и игры.
- На смех («гы-гы», «ахаха», «хихи», «лол», «ржу») и радостные возгласы («ура», «еее», «ыыы», «уху», «юху», «кайф», «поехали», «супер», «имба», «изи», «го», «да!» и похожие) Настя сразу отвечает одним из 12 реакционных стикеров. Другие персонажи отвечают на радость в своём характере. Обычное «да ну тебя» стикер не вызывает. Для каждого героя подготовлено не менее 500 коротких тематических шуток (3700 вариантов сцен); устройство списков и темы описаны в [правилах персонажей](docs/character_behavior.md). Старый общий сборник из 1018 вариантов сохранён как прежний материал; активные ответы используют личные списки.
- Бот поддерживает семейный формат общения и не создаёт откровенный контент.
- На праздничные слова и поздравления отвечает выбранным персонажем. Персонажи используют готовые стикеры, если для них есть подходящий сюжет; без подходящей иллюстрации модель ответит текстом.
- «Анекдот», «расскажи анекдот», «юмор» и похожие запросы без имени выбирают одного случайного персонажа и его личный тематический список. «Настя юмор» отвечает только Настей, «Ракета и Грут юмор» — обоими. Указанная тема направляет запрос подходящему специалисту.
- По команде `/news` или запросу вроде «новости США», «новости Китая», «новости ИИ», «новости серверов» получает до восьми свежих заголовков за 24 часа из GDELT, переводит заголовки на русский через выбранную модель LM Studio и прикладывает ссылки на оригиналы. GDELT не требует API-ключа. Это подборка заголовков, не полный перевод статей.
- Закрытая панель владельца: выбор модели LM Studio, персонажа по умолчанию, стиля, дополнительного контекста персонажа, группового режима, доступов и очистка истории.
- Входящие запросы идут через общую FIFO-очередь: за раз обрабатывается один запрос, размер буфера задаётся владельцем в `/admin` от 1 до 65 536 сообщений (произвольное значение — командой `/queue_limit N`). При переполнении самое старое ожидающее сообщение удаляется без ответа, а новое добавляется в конец.
- В `/admin` можно отдельно задать общий для всех пользователей характер каждого персонажа: радостный, грустный, игривый, весёлый, серьёзный, вдумчивый, хаотичный, злой, спокойный, заботливый и другие стили, включая случайный. Игривый стиль выбран по умолчанию для Котика и Пёселя. У Насти дополнительно есть стиль «учительница». Все стили остаются в семейном формате. Откровенных режимов нет.
- «Эмодзи» или `emoji` выбирает случайного персонажа и его случайную эмоцию; имя с эмоцией (например, «Настя злая» или «Наташа печальная») выбирает конкретный стикер из личного набора. Готовы 56 отдельных прозрачных стикеров настроений — по восемь на героя. Список и маршрутизация: [docs/emotion_stickers.md](docs/emotion_stickers.md).
- «Стикер» или «картинка» (также sticker, picture, image) без имени выбирает случайного персонажа, затем случайный стикер из его активной коллекции. «Настя стикер», «Натусик картинка» или «Blonde sticker» выбирают только указанного героя. «Команда картинка» отправляет по стикеру от всех по очереди. Праздничные запросы сохраняют свой обработчик. Запросы на откровенный контент не получают стикер. Обычный случайный выбор не включает архивы.
- «Новый год!», «Рождество!», «8 марта!», «23 февраля!», «1 мая!» и «9 мая!» без имени вызывают стикеры всех семерых последовательно в случайном порядке. Имя или алиас ограничивает ответ: «Черри с Рождеством» — только Настя, «Ракета и Грут с Новым годом» — только эти двое. [Полный справочник имён и алиасов](CHARACTER_ALIASES.md).
- «Команда А», «Тима как дела?», «Друзья и подруги ау», «Друзья», «Банда» и «Тусовка» вызывают всех семерых. Порядок случайный, ответы идут последовательно; вызовы в одном чате не перемешиваются. «Ракета и Грут привет» вызывает только Ракету и Грута; аналогично можно назвать любую пару или группу. «Подруги ау» вызывает Настю и Наташу. Поддерживаются русские и английские имена.
- Можно ответить непосредственно на сообщение бота или сослаться словами «посмотри сообщением выше», «ответь на предыдущее», «ответь через одно», «ответь на -1 сообщение», «ответь на -2 сообщение» и так далее. Общая настройка «Память диалога» в `/admin` определяет, сколько сообщений запоминать и передавать модели; по умолчанию — 50, варианты от 10 до 200. История включает стикеры, чтобы бот мог восстановить вопрос, на который отправил стикер.
- Можно попросить персонажа проанализировать последние сообщения автора: укажите число, например «проанализируй 30 последних сообщений», или не указывайте — тогда будет выбрано случайное количество от 10 до 30. В `/admin` лимит хранения для анализа настраивается от 0 до 65 535 (начально 100; 0 отключает функцию), точное значение также задаётся командой владельца `/analysis_limit N`. В группах анализируются только сообщения автора запроса в текущем чате.
- Отдельная история диалога для каждого пользователя или группы, с ограничением длины.
- Бот автоматически покидает группы, куда его добавил пользователь, чей Telegram ID не совпадает с `OWNER_ID`.
- Владелец управляет списками пользователей и групп/каналов, где бот имеет право отвечать, через `/admin` и команды доступа.
- Бот работает в группах и каналах, где Telegram позволяет ему получать сообщения и отправлять ответы. Для чтения обычных сообщений группы отключите privacy mode у бота через BotFather и при необходимости выдайте права администратора. В каналах ему потребуются права публикации.
- Настройки и история хранятся в `data/state.json`; файл локальный и исключён из Git.
- Подробные логи пишутся в окно запуска и `logs/bot.log` (папка исключена из Git; файл ротируется до четырёх файлов примерно по 5 МБ). `BOT_LOG_LEVEL` в `.env` настраивает уровни `TRACE`, `DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL`; `WARN` — синоним `WARNING`, `FATAL` — `CRITICAL`. Тексты запросов пишутся в локальный лог; известные форматы токенов Telegram/API маскируются.
- По запросу показывает сведения о видеокартах NVIDIA из `nvidia-smi`, использовании RAM и файла подкачки, процессоре, версии/сборке Windows и диске моделей `L:`. Тип и скорость модулей RAM и температура накопителя доступны, если их раскрывают системные драйверы; активную канальность и температуру CPU стандартные интерфейсы Windows могут не предоставлять.
- Запрос GPU-статистики распознаёт алиасы «видеокарта», «Video», «GPU/гпу», «графика/graphics/grapphics», «3D accelerator / 3д акселератор» и «ускоритель».
- Статистика CPU вызывается по словам «процессор», «проц», «камень», `CPU`/«цпу» и `processor`; оперативная память — «оперативка», «ОЗУ», `RAM`, `DDR` и «память»; накопители — «диск», «накопитель», «хранилище», `SSD`, `NVMe`, `HDD`, `drive` и `storage`.

## Запуск

1. Установите Python 3.11+ и создайте бота через [@BotFather](https://t.me/BotFather).
2. Скопируйте `.env.example` в `.env`, добавьте токен и Telegram ID владельца. ID можно узнать у информационного бота Telegram; управление ботом проверяется по этому ID.
3. Запустите `start_bot.bat` двойным щелчком. При первом старте скрипт создаст `.venv` и установит зависимости. Либо выполните вручную:

   ```powershell
   py -3.11 -m venv .venv
   .\.venv\Scripts\Activate.ps1
   pip install -r requirements.txt
   Copy-Item .env.example .env
   # Отредактируйте .env: BOT_TOKEN и OWNER_ID обязательны.
   python -m bot
   ```

4. Откройте LM Studio, загрузите модель и запустите Local Server на `http://localhost:1234`. Оставьте стандартный OpenAI-compatible API или поменяйте `LM_STUDIO_BASE_URL`.
5. Напишите боту `/admin`, выберите модель и стиль по умолчанию. В пункте «Характер каждого персонажа» можно отдельно задать стиль каждому персонажу, включая случайный; настройки общие для всех пользователей бота.

Для остановки нажмите `Ctrl+C` в окне бота или запустите `stop_bot.bat`. Чтобы перезапустить бота после изменения кода или `.env`, дважды щёлкните `restart_bot.bat` — он остановит экземпляр этого проекта и запустит его в новом окне.

Бот и LM Studio должны быть доступны друг другу по сети. При запуске на другом компьютере замените `localhost` на адрес компьютера с LM Studio. Не публикуйте LM Studio API наружу без защиты. Если в LM Studio включена проверка API key, задайте его в `LM_STUDIO_API_KEY`; если выключена, оставьте поле пустым.

`SYSTEM_PROMPT` задаёт базовый характер Насти, а `PESEL_SYSTEM_PROMPT` — Пёселя. Для Котика, Ракеты, Грута/Клёна, Стича и Наташи заданы характеры по умолчанию в проекте. В `/admin` кнопки «Характер каждого персонажа» и «Язык каждого персонажа» настраивают общие для всех пользователей параметры отдельно для каждого персонажа. Язык по умолчанию — русский; доступны также английский, французский, немецкий, испанский, китайский, японский, корейский, хинди, идиш, белорусский, финский и ирландский. В сообщении можно переключить язык в текущем диалоге, например: «Настя, отвечай на английском»; выбор сохранится только для вас в этом чате и персонаже, пока вы не попросите другой язык, и не изменит настройку админки. В `/admin` выберите персонажа по умолчанию, затем кнопкой «Контекст / персонаж» задайте только его дополнительный контекст. `/reset_prompt` сбрасывает контекст выбранного персонажа. Персонажи, явно названные в сообщении, переопределяют значение по умолчанию. Размер окна контекста настраивается в LM Studio при загрузке модели; `CONTEXT_LENGTH` документирует выбранное значение.

Активный праздничный план полностью выполнен: 333 WebP-стикера исходного плана, один бонусный и пять дополнительных праздничных стикеров Ракеты (всего 339). В `assets/stickers/characters` лежат шесть полных 54-стикерных наборов Насти, Наташи, Котика Мяу, Пёселя, Грута/Клёна и Стича; у Ракеты — 9 плановых новогодних стикеров, один бонус и по одному стикеру для остальных пяти праздников. Все активные праздничные WebP имеют размер 512×512 и прозрачность. Подробная сегментация по персонажам и оставшиеся задачи визуальной проверки приведены в [таблице состояния персонажей](docs/character_asset_status.md) и [плане стикеров](docs/sticker_migration_plan.md). В `assets/stickers/imports` сохранены исходные файлы прежних проектов, включая PNG, SVG, превью и описания. Также есть семейные реакции на смех и радость и общие сюжеты — сон, возвращение, ученик, игры, кофе, физика, математика и IT. Откровенные запросы стикер не получают. Бот запоминает до 50 стикеров, полученных от разрешённых пользователей в личке или разрешённых чатах, как запасные.

Системные контексты персонажей и стилевых режимов написаны по-английски. Язык ответов каждого персонажа выбирается в админке; по умолчанию используется русский. Пёсель передаёт их лаем и действиями с переводом на выбранный язык, Котик — мяуканьем и действиями с переводом на выбранный язык; Стич отвечает в смешной мультяшной манере, а каждый текстовый ответ Грута содержит «Я есть Грут». Английский шаблон контекста доступен в кнопке «Контекст / персонаж».

Запросы оборудования, новостей, праздников, просьбы пошутить, радостные возгласы и явное имя любого персонажа считаются прямым обращением в группе; пользователи и группы всё равно должны быть разрешены владельцем. Персонаж выбирается независимо от функции: например, «Котик, видеокарта», «Пёсель, видокарат», «Ракета, память», «Грут, диск» — системные запросы всё равно идут в соответствующий обработчик железа. Поддерживаются также «операта», «камень», «оська», «NVMe», «ссд» и другие варианты. Для новостей подойдут `/news`, «новости США», «новости Китая», «новости ИИ», «новости серверов», «последние события».

Запросы оборудования: например, отдельные слова «диск», «память», «операта», «проц», «графа», «SSD»/«ссд», «NVMe»/«нвме», а также вопросы «какая температура видеокарты?», «сколько оперативки занято?», «какой процессор и сколько ядер?», «какая версия Windows?», «сколько места занято на диске L?». Статус включает GPU, VRAM, загрузку, питание, частоты, ширину шины GPU и интерфейс PCIe; RAM и доступные Windows сведения о модулях; CPU; версию Windows; диск моделей `L:`. Показатели оборудования доступны только владельцу и ID из `/allow_system`. Бот только читает показатели. Некоторые датчики и характеристики Windows не предоставляет — тогда бот так и укажет. `nvidia-smi` должна быть доступна в `PATH` на компьютере с ботом.

## Команды

### Управление всеми Telegram-ботами на этом компьютере

В папке `scripts\bots` находятся общие `.bat`-скрипты:

- `start_all_bots.bat` — запускает найденные проекты в отдельных окнах;
- `stop_all_bots.bat` — пытается закрыть ботов и принудительно завершает их процесс, если он остался;
- `restart_all_bots.bat` — останавливает и запускает найденные проекты заново;
- `kill_all_bots.bat` — принудительно завершает процессы ботов.

Скрипты управляют единым проектом `TelegramBot`, отмеченным модулем `bot\personas.py`; теперь персонажи работают внутри него под одним Telegram-токеном. Завершаются только `python -m bot` из `.venv` этого проекта, остальные Python-процессы не затрагиваются. Отдельные токены для Пёселя, Ракеты, Грута/Клёна и Стича не нужны.

- `/start` — приветствие.
- `/admin` — панель владельца (доступна только `OWNER_ID`).
- `/mode` — текущий стиль.
- В `/admin` выбери персонажа по умолчанию; явное имя в сообщении переключит его на время ответа. Кнопка **«Контекст / персонаж»** редактирует контекст выбранного персонажа; `/reset_prompt` сбрасывает его.
- `/clear` — очистить историю текущего разговора у всех персонажей; личные факты удаляются отдельно в админке.
- `/memory` — посмотреть сохранённую память о себе всех персонажей; «Наташа память обо мне» — только Наташи.
- Обычный контекст: `/admin` → «Контекст каждого персонажа», по умолчанию 5 сообщений, диапазон 0–65535. Любое значение задаёт владелец: `/context_window Наташа 17`.
- `/help` — справка. Попросить анекдот можно по конкретной теме, например «анекдот про физику», «шутка про математику», «прикол про химию», «анекдот про программирование» или «шутка про сервер».
- `/news [страна или тема]` — свежие заголовки за последние 24 часа; примеры: `/news`, `/news США`, `/news Китай`, `/news ИИ`, `/news серверы`, `/news политика`. Ищет GDELT через интернет с компьютера, на котором запущен бот; для перевода нужен выбранный и доступный сервер LM Studio. Бот показывает первоисточник и дату публикации.
- Неизвестный пользователь может написать `/start`; его запрос появится в админке, где владелец сможет нажать «Разрешить».
- `/allow_user TELEGRAM_ID` и `/deny_user TELEGRAM_ID` — управлять доступом пользователей (только владелец). Вместо ID можно ответить соответствующей командой на сообщение пользователя и указать его `@username`, например `/allow_user @nickname` или `/deny_user @nickname`.
- `/allow_system TELEGRAM_ID` и `/deny_system TELEGRAM_ID` — отдельно разрешить или запретить этому ID запрашивать сведения о GPU, RAM, CPU, Windows и диске `L:`. Это разрешение не выдаёт доступ к обычному общению. Для username ответьте командой на сообщение этого пользователя и добавьте его `@username`.
- `/allow_chat TELEGRAM_ID` и `/deny_chat TELEGRAM_ID` — разрешить или закрыть группу/канал (только владелец).
- `/allow_here` — разрешить текущую группу (только владелец, команда в группе).
- `/deny_here` — запретить ответы в текущей группе, оставив бота в ней. Из личного чата `/deny_here TELEGRAM_ID` или `/deny_here @username_канала` отключает указанную группу/канал.
- `/leave_here` — удалить бота из текущей группы/супергруппы. `/leave_chat TELEGRAM_ID` или `/leave_chat @username_канала` из личного чата выводит его из указанной группы или канала. В обоих случаях чат удаляется из списка разрешённых.
- `/allow_channel @username` — разрешить канал по username (только владелец).
- `/access` — показать оба списка; `/id` — показать ID текущего чата (только владелец).

Владелец всегда имеет доступ. Остальным бот отвечает только после добавления их Telegram ID через `/allow_user`. Группы и каналы допускаются отдельно через `/allow_chat`. Данные компьютера (GPU, RAM, CPU, Windows и диск `L:`) по умолчанию видит только владелец; выдайте отдельное разрешение командой `/allow_system TELEGRAM_ID` или кнопкой «Доступ к данным системы» в `/admin`. Отзыв — `/deny_system TELEGRAM_ID`. Для получения ID владелец отправляет `/id` в нужном чате. Для канала можно использовать его числовой ID (обычно начинается с `-100`) или username канала в Bot API, а боту нужны права администратора на публикацию. Для новых групп действует также проверка, что бот добавлен владельцем. Кнопки «Кому отвечать» и «Допустимые группы и каналы» в `/admin` показывают списки. Команды `/deny_here`, `/leave_here` и `/leave_chat TELEGRAM_ID` доступны только владельцу.

В группах режим задаётся кнопкой «Групповой режим» в `/admin`: `mentions` отвечает на `@username` или ответ боту; `keywords` (по умолчанию) — на эти обращения, русские имена и зазывалки. Несколько названных русских или английских имён вызывают именно перечисленных персонажей по очереди в случайном порядке. `Team, are you there?` и другие поддерживаемые командные фразы также вызывают всех. `Nasty` распознаётся и отдельно, и в списке имён. Отдельное слово `Wow` намеренно не считается вызовом Пёселя, чтобы обычное «wow!» не было ошибочно принято за обращение. Регистр не важен; некоторые растянутые слова и близкие опечатки распознаются. Для Насти также работают цифры после имени («Настя2000», «Настя777», «Настюха2000», «Черри2000») и растянутые варианты («НННастя», «ННННаааастяяя»); «Анна» иногда вызовет уточнение «Вы не ошиблись? Я Настя». Запросы новостей, статистики, тематического стикера, просьба об анекдоте и явный смех тоже считаются прямым обращением в режимах `mentions` и `keywords`. При прямом обращении к боту в личке или группе через `@username`/ответом без имени и профильной темы выбирается один случайный персонаж из всех семи; имя выбирает указанного героя, профильная тема — специалиста, командный вызов — всех участников. `context` передаёт сообщения модели, которая отвечает только если по смыслу к ней обратились; `all` отвечает на каждое сообщение. Для получения обычных сообщений группы отключите Group Privacy в BotFather.

## Если бот молчит в группе

1. Убедитесь, что окно `start_bot.bat` всё ещё открыто, а LM Studio запущена, модель загружена и Local Server включён.
2. Проверьте личный чат с ботом: отправьте `/start`, затем `/admin`. В админке нажмите «Обновить модели LM Studio» и выберите модель.
3. В группе отправьте отдельное сообщение с упоминанием, например `@имя_вашего_бота привет`, или ответьте на сообщение бота. Для обращения по смыслу без `@` включите в `/admin` режим `context`.
4. Если в личном чате бот отвечает, а в группе нет, откройте настройки бота в `@BotFather`: `/mybots` → выберите бота → **Bot Settings** → **Group Privacy** → **Turn off**. После изменения удалите бота из группы и добавьте его снова.
5. В `/admin` кнопка «Групповой режим» циклически переключает `mentions` → `keywords` → `context` → `all` → `mentions`.

Если `start_bot.bat` завершился с ошибкой, проверьте её текст в окне запуска. Не публикуйте `.env`, токен Telegram или API-ключ LM Studio.

Долговременная память персонажей о пользователях: [настройка, просмотр и очистка](docs/user_memory.md). Управление находится в `/admin` → «Память о пользователях»; по умолчанию выключена.

## Кто может добавить бота в группу

Telegram не предоставляет боту настройку, которая запрещает другим людям нажать «Добавить в группу». В проекте действует ограничение на стороне бота: при добавлении в группу бот проверяет, кто его добавил, и остаётся только если ID добавившего совпадает с `OWNER_ID`. В остальных случаях бот автоматически покидает группу. Это ограничение начинает работать, когда бот запущен; оно не отменяет уже выданное доверенным участникам право добавлять ботов в настройках самой группы.

## Notio: заметки через бота

Модуль `bot/notio_relay.py` связывает бота с приложением Notio на компьютере: бот передаёт поручения в нужный Notio по
коду из 12 символов. Telegram по-прежнему читает только этот бот; Notio сам подключается к боту по HTTP.

1. В Notio: Настройки → Помощник → Telegram-бот → «Через вашу программу-бот (TelegramBot)». Notio покажет код.
2. В боте: `/admin` → «🗒 Notio» → «➕ Ввести код Notio», отправить код (можно с именем: `ABCD-EFGH-JKMN Дом`) или
   `/notio_add КОД имя`. Бот хранит только SHA-256 кода; Notio с незнакомым кодом не пускает.
3. Пользователь: `/notio КОД` — подключиться (сообщение с кодом бот удаляет), `/n поручение` — отправить,
   `/n_undo` — откатить, `/n_yes` — подтвердить, `/notio_off` — отключиться; `/notio КОД поручение` — сразу.
4. Кому отвечать, решает Notio: человек должен быть отмечен в Notio в списке «Кто писал через бота».

Работает только в личных чатах. Обычные сообщения по-прежнему идут персонажам; в Notio — только команды выше.
HTTP для Notio слушает `NOTIO_RELAY_HOST:NOTIO_RELAY_PORT` (по умолчанию `127.0.0.1:8790`, только этот компьютер). Если
Notio на другом компьютере, задайте адрес домашней сети или VPN; шифрования между ботом и Notio нет — в интернет порт не
открывайте. Тесты: `python -m unittest tests.test_notio_relay`.
